Compute Efficiency Is the New Scaling Law: How MAI Gets 4–12× More from Each FLOP

By Esther Xin

MAI combines precise scaling science, a sparse MoE design, the efficient Muon optimizer and purpose-built infrastructure to get far more from every unit of compute.

Two ways to make a model smarter

Spend more: Train a bigger model on more data with more compute.

Spend smarter: Get more out of each unit of compute with better training methods.

MAI-Base-2 does both, and it shows how far spending smarter can go.

The headline: 4–12× more from every FLOP

MAI's scaling-law analysis shows its recipe for MAI-Base-2 is 4–12× more pre-training-FLOPs-efficient than DeepSeek-V4-Pro-Base, the strongest open base model it tested. In plain terms: to reach the same quality, MAI's recipe needs only a fraction of the compute. MAI put that gain straight back into capability, building a much bigger and stronger model.

How MAI did it: 3 smart levers

Lever What MAI did Why it saves compute
1. Scaling science

Scaling ladders: before the big run, MAI trains a series of small models at growing sizes and tracks how quality improves as size and data grow. The ladders also account for reusing the same high-quality data more than once.

Hyperparameter scaling laws: MAI measured how the best training settings, such as learning rate, shift with model size, so the big run starts with the right settings from day one.

 Small runs accurately predict the big one, so no compute is wasted on guesses
2. Model + infrastructure co-design

Mixture of experts (MoE): the model is split into many smaller "expert" parts, and only a few are switched on for each word, so it can be huge while each step stays cheap. MAI rebuilt how these experts run on its GPUs.

Muon: a stronger optimizer, the rule that decides how the model updates itself at each step; MAI made it run efficiently at scale.

Activation gradient clipping: caps unusually large update signals, so one bad step can't knock the run off course.

 The model runs fast on the hardware and stays stable at huge scale
3. Scaling data

Bigger data pipelines: MAI expanded the systems that collect, clean and filter training data, reaching about 50T tokens. Vision data: images paired with text were built into training, so the model learns from both.

Organic data, no distillation: the model learns from real-world data, not by copying answers from other AI models.

 More useful learning per FLOP, with full ownership of what the model learned

The payoff: a bigger, stronger model

MAI-Base-1 MAI-Base-2
Active parameters 35B 80B
Total parameters 1T 2.8T

MAI-Base-2 is a mixture-of-experts model: it uses only a small part of its network for each token. That lets it grow 2.8× larger while keeping the cost of each prediction low. It learned from about 50T tokens, including vision-language data.

Keeping 16,000 GPUs productive

Metric MAI-Base-2 What it means
Hardware 16k GB200 GPUs Frontier-scale training, openly published
Duration 38 days The full pre-training run, start to finish
Goodput 89% Share of time the run was making real progress

At this scale, hardware hiccups are routine. Keeping 89% goodput across 16,000 GPUs shows a training system built to keep moving forward.

Efficient from training to serving

Post-training: MAI's Rocket RL framework recovers and reconfigures without restarting, saving an estimated 2.6M GPU-hours in RL training.

Serving: MAI's Maia 200 chip delivers 1.7× more tokens per watt.

Why it matters

Cost: Getting more from each unit of compute makes models cheaper to build and to run.

Capability: Saved compute can be turned into a bigger, stronger model.

Independence: Owning the full stack, from data to chip, lets MAI tune model and infrastructure together.

Takeaway: MAI predicts the big run with small ones, builds the model and infrastructure as one system, and keeps a huge run productive almost all the time. The result: a far larger, stronger model from a smarter use of compute.
